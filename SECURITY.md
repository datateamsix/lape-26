# Security Policy

## Supported versions

Only the latest tagged experimental or stable release receives security fixes.

## Reporting

Please do not publish vulnerabilities involving executable code, dependency compromise, study participant privacy, or data exposure in a public issue. Contact the project maintainer privately through the repository security-reporting channel.

Include:

- Affected version or commit
- Reproduction steps
- Potential impact
- Suggested mitigation, when known

## Research-data privacy

Listener-study exports must not contain names, email addresses, precise location, IP-derived identity, or other unnecessary personal identifiers. Public datasets should use anonymous IDs and documented consent.
